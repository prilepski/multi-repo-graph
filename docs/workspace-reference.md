# Workspace reference — `codegraph-workspace`

A workspace is the per-company (per-user) git repo that owns the repo
list, every indexed snapshot, and the deployed runtime. It is the only
thing consumers ever clone. One tool installation can drive many
workspaces (e.g. `codegraph-workspace` and `demo-graph`), each with
its own ports, container, and remote.

## Layout

```
<workspace>/
  workspace.json        repos + settings + remote  (validated by the tool)
  latest.json           {"run": "<latest run id>"} (written by publish)
  runs/<UTC-ts>/        snapshots — committed (LFS for *.zst)
    run-manifest.json     runId, tool versions, schema fingerprint, per-repo
                          commitSha / LOC / artifact SHAs, verification status
    summary.json          full per-repo verification report
    neo4j/neo4j.dump.zst  portfolio graph (zstd)
    neo4j/system.dump.zst credentials (users/roles — REQUIRED to log in)
    codegraphs/<repo>/codegraph.db.zst
  runtime/              deployed by stage 8 — committed
    VERSION              tool commit + deployedAt + codegraph version
    mcp-server/ codegraph-mcp/ graph-viewer/   (source copies)
    scripts/up.py down.py up.sh up.ps1 down.sh down.ps1
    config/              generated by up.py (gitignored)
  repos/                gitignored — repo clones (input cache + MFLens reads)
  snapshot/             gitignored — materialized state for services
  logs/                 gitignored — pipeline logs + staging
```

## `workspace.json`

```json
{
  "repos": [
    {
      "name": "thingsboard",                          // required, unique
      "cloneUrl": "https://github.com/…/thingsboard.git",
      "path": "repos/thingsboard",                    // workspace-relative
      "shallow": true                                 // default true
    }
  ],
  "settings": {
    "keepLast": 3,                                    // runs kept in tree
    "concurrency": null,                              // stage-2 pool size
    "viewerPort": 7600,
    "neo4j": {
      "boltPort": 7688,
      "httpPort": 7475,
      "password": "graphpassword123",
      "container": "mrg-neo4j-instance"              // ingest container name
    }
  },
  "remote": { "push": false }                         // push runs to origin
}
```

Rules: `repos` is required, non-empty, names unique. `path` used if the
checkout exists — it must be a git repo with a **clean tree** (untracked
build residue fails the run unless `--force-clean`, which `git clean`s it;
`.codegraph/` is always exempt). Missing `path` + `cloneUrl` → shallow
clone into `path`. Docs-only repos (wikis) are fine: zero codegraph files
→ inventory-only in the graph. `container` must be unique per workspace
sharing one Docker host.

## Lifecycle

**Index (operator, from a tool checkout):**

```bash
indexer/.venv/bin/python -m indexer.pipeline \
    --workspace /path/to/codegraph-workspace \
    [--force-clean] [--publish-dry-run] [--concurrency N]
```

Runs stages 0–8, commits the run (+ runtime) into the workspace, pushes
when `remote.push`, stops the ingest container. `--publish-dry-run`
builds the commit without pushing.

**Consume (anyone with a clone):**

```bash
runtime/scripts/up.sh        # or up.ps1 — needs only Python 3.11+ located
runtime/scripts/up.sh --run 2026-11-08T22-13-41Z   # pin a specific snapshot
runtime/scripts/up.sh --mode live                  # codegraph from working
                                                    # trees instead of snapshot
runtime/scripts/down.sh [--purge]
```

`up.py` (all logic in Python; sh/ps1 only find a Python): checks
Docker/Node/npm → builds `runtime/.venv` (+ deps incl. zstandard) →
npm-installs the pinned codegraph SDK → restores Neo4j from BOTH dumps
(volume → container, bolt/http from settings) → decompresses codegraph
DBs into `snapshot/codegraphs/<repo>/.codegraph/` → checks `repos/` out
at the SHAs recorded in the run manifest → writes
`runtime/config/{mflens-repos.json, codegraph-repos.json, mcp.json}` →
starts the viewer.

Outputs:

- Neo4j browser `http://localhost:<httpPort>` (bolt `<boltPort>`,
  password from settings)
- graph viewer `http://localhost:<viewerPort>`
- MCP registration: paste the `mcpServers` block from
  `runtime/config/mcp.json` into your ZCode/Claude config — registers
  **mflens** (Neo4j portfolio) and **codegraph-portfolio** (fan-out)

## Concurrency note (one machine, several workspaces)

Give each workspace distinct `boltPort`/`httpPort`/`viewerPort` and its
own `container` name. The pipeline stops its ingest container after
dumping precisely so a restored consumer container can bind the same
ports; integration tests re-start the ingest container themselves when
they need it.

## Artifacts & retention

Every run is a new timestamped dir; `keepLast` (default 3) prunes older
dirs from the tree after a successful publish — history keeps them
(rollback = `git checkout <run-dir>^`). `*.dump.zst` / `*.db.zst` are
LFS-tracked (git-lfs must be installed where you push from). Run
manifests record sizes + sha256 per artifact — the O3 measurements for
retention planning.
